# 个人健康助手的记忆构建与召回

你有完整两小时，实现一个能持续更新、持久化并按观察点召回的个人记忆系统。结束时一次性交付；面试官随后统一验收。自行决定是否使用 AI 编程工具。不要求 AI 对话或提示词记录、录像、开发轨迹、过程汇报、中途检查点、演示或答辩。只评价提交代码、可运行系统、构建产物和验收结果。

## 场景与数据

同一账号与健康助手持续交流，内容涉及本人、家人及一般健康知识。事实可能补充、变化或澄清。输入为16段中文完整会话：初始10段、增量6段，共228条消息。初始和增量的接收顺序是固定的，不随机切分。两份文件共约306 KB，原消息正文约10.7万 Unicode 字符。无需人工逐条制作答案或阅读所有医学讨论；请实现可复用的构建与检索流程。

健康内容只作为对话事实：不要求临床诊断、医学知识核验或诊疗建议。不得用外部医学知识补全记录未提供的个人事实；不能把助手分析、建议、假设直接当成用户已发生的事实。原始数据可能有不一致或角色表达含糊，保留原文证据、按已有信息说明边界即可，不要求修复医学时间线。

`user_id=u001` 表示账号，不意味着正文中每个人都是本人。`sequence` 是本题接收顺序，包含会话内全部消息；`recorded_at` 是可确认的来源会话记录时间。此子集没有可靠的会话记录时间，统一为 `null`。正文中出现的年龄、过去几天、月日属于事件时间，不能随意补出年份或当成会话日期。原始会话编号不唯一，因此已统一映射新ID；无需恢复上游ID或读取上游标注。

## 必做功能

1. **构建**：构建不接收查询，生成查询无关、可供未来问题复用的记忆。保留主体、事实精度、时间、状态和不确定性，持久化；每条可追溯原始 `message_id`，保存原始记录供证据核验。可以使用简单检索索引、结构化事实或其他设计；不能只硬编码公开问题答案，也不能每次查询把全部历史送给模型重读。
2. **更新**：先初始、后增量。新信息改变“目前/最近”的召回，旧事实仍可查询。重复导入同一会话应跳过，不产生重复事实或改变已有事实含义。错误情况下保留明确的完成/失败信息。
3. **召回**：输入自然语言问题与 `as_of_sequence=N`，只能使用第1至N段中已经获知的信息。即使全量导入，也必须能查旧观察点；后续消息重述旧事实，也不能作为早观察点的证据。支持具体事实、当前状态、历史变化、多证据组合；区分本人/家人，以及建议、意愿、计划、询问、推测和已执行行为。信息不足返回 `insufficient`，可附已知边界的记忆与证据；确无相关个人记忆的无关问题可返回 `ok` 与空列表。
4. **工程**：重启后直接查询既有存储；可导出内部记忆及来源，方便检查历史保留和幂等。非法参数、空白问题、损坏JSONL、存储不存在、解析或模型调用失败须明确报错。无模型实现无需伪造模型失败测试。实现语言、存储、检索和是否调用模型自由，不按框架复杂度、组件数量或技术选型评分。

无需前端、部署、账号、多用户、并发服务、最终医疗回答或复杂基础设施。优先完成最小可验收系统。

## 输入格式

`data/initial.jsonl` 和 `data/incremental.jsonl` 为 UTF-8 JSONL，每行一个完整会话，仅包含：

```json
{"user_id":"u001","session_id":"s001","sequence":1,"recorded_at":null,"messages":[{"message_id":"s001-u01","role":"user","content":"原始消息"}]}
```

实际文件保留所有选中用户与助手消息的原文、角色、会话内顺序。消息ID中的 `u` / `a` 分别标识 user / assistant，后两位是该角色在会话内的序号。输入不包含画像、事件说明、知识点或标准问答。

## 统一入口与输出

提交根目录必须有可执行 `run.sh`。面试官从提交目录执行以下入口，参数路径可为绝对路径。依赖安装按你的说明预先完成，启动不要求人工交互。

```bash
./run.sh ingest --input data/initial.jsonl --store ./store
./run.sh ingest --input data/incremental.jsonl --store ./store
./run.sh query --store ./store --query "问题" --as-of-sequence 10 --top-k 8
./run.sh export --store ./store
```

每次命令的 stdout 只能是**一个有效JSON值**，日志放 stderr；禁止 Markdown 代码围栏。正常命令退出码0；错误退出码非0并返回 `{"status":"error","error":{"message":"具体原因"}}`。`error` 也可为非空字符串；若能判断外部服务故障，可额外给 `error.category="external_service"`，请保留真实错误依据，不把实现错误伪装为服务故障。失败查询可附 `as_of_sequence` 和空 `memories`。部分导入失败仍须报告下列计数和已知usage；未完整构建时usage.complete=false。整个文件无法解析时可直接明确报错。

`as_of_sequence` 为正整数且不得超过当前导入的最大sequence；`top-k` 为1至8的整数；空白问题非法。每条有效JSONL会话原子处理或清楚说明部分失败；不要求事务数据库。

正常 `ingest` 输出：

```json
{"successful_sessions":10,"skipped_sessions":0,"failed_sessions":0,"failed_session_ids":[],"usage":{"complete":true,"models":[]}}
```

计数是本次命令的新增、已存在跳过和失败会话数，合计等于输入会话数；失败ID不重复。正常初始为10/0/0、增量6/0/0；重复初始0/10/0、重复增量0/6/0。usage缺失不会影响质量或工程分，但报告会显示计量不完整。

查询输出：

```json
{
  "status":"ok",
  "as_of_sequence":10,
  "memories":[
    {
      "memory_id":"稳定ID",
      "subject":"self",
      "text":"简洁事实；需要时包含时间、性质与不确定性",
      "source_ids":["s006-u01"],
      "evidence":[{"message_id":"s006-u01","quote":"原消息中的连续原文片段"}]
    }
  ],
  "usage":{"history_input_chars":0}
}
```

这是字段示意，不是实际案例。`status` 为 `ok`、`insufficient` 或 `error`。`subject` 使用清晰稳定的主体标签，如 `self`、`father`、`family_unspecified`、`general`，不限枚举。每条实质记忆的text非空，ID稳定且本次输出不重复；`source_ids` 与 `evidence.message_id` 对应，每个来源至少有一段连续原文引文。可在一条记忆中组合多条证据；原文可来自助手，但只能支持助手说过的内容，或与用户证据共同支持结论。不得静默把建议变为执行。

`export` 的内部JSON schema自由，至少应便于检查记忆、主体、状态、原始来源及更新历史，直接查看持久化产物也可以。导出不必限制为查询的2,400字符。

## 召回预算

- 最多返回 `top-k` 条，且不超过8条，不必凑满。
- 所有 `text` 和 `evidence.quote` 字符数相加不超过2,400，按 Python `len(str)`；重复文本、重复引文每次都计入。
- 每次query所有模型调用中发送的**历史内容**总计不超过6,000字符，包括记忆、摘要、候选原文、重排输入；多次发送重复计数。固定指令及当前问题不计入；不得把历史伪装成指令绕过预算。
- 可报告 `usage.history_input_chars`；没有任何模型调用时为0。字段可省略，面试官通过源码/日志人工核验；自报0不自动证明合规。若查询时调用embedding或重排，发给它们的历史文本也计入。
- 返回内容无需生成最终自然语言医疗回答。未知问题可返回有证据的边界说明；只有 `insufficient` 而未说明已知边界，在对应信息不足题中最多获得部分分。

## 公开自测与验收方式

`public_cases.json` 有2个示例，展示查询、观察点及一种允许输出；不要求文本逐字一致。面试官会先导入初始、查询初始观察点，再导入增量、查询当前与历史状态和多证据/主体/未知/无关问题；全量导入后回看旧观察点，再各重复导入一次并用独立进程查询、导出。会检查上述错误情况、源码、测试和构建产物。隐藏的是具体问题与参考事实，没有额外隐藏功能要求。

五项共100分：

| 项目 | 分值 | 公开验收能力 |
|---|---:|---|
| 记忆构建与事实边界 | 20 | 查询无关可复用表示、事实精度与来源、主体区分、陈述性质；各5分 |
| 状态更新与时间 | 20 | 当前与旧值共存、会话内部变化/澄清、观察点隔离、事件与记录时间区分；各5分 |
| 召回质量 | 30 | 15个隐藏案例各0/1/2分；完整正确2，部分关键事实且无关键错误1，错误/主体错/泄漏/编造0 |
| 来源与可核验性 | 10 | 机械有效引用比例5分；5条实质召回的证据语义支持各1分 |
| 工程可用性 | 20 | 可运行复现、持久化恢复、增量幂等、错误处理与执行状态；各5分 |

构建、状态、工程每单项完整5分，部分2或3分，缺失/持续错误0分。至少一个隐藏案例在初始和全量回看时各验一次，取较低分，只算一个案例。无关题正确空结果可以满分。人工判断语义，不用关键词匹配替代事实判断。

机械引用以全部隐藏案例中唯一 `message_id` 为单位去重，同一来源任何出现不合法，该单位即无效；同一来源重复多次或引用多个片段不能抬高比例。无来源的实质文本按主体+文本去重计为无效单位，零引用得0分。核验来源存在、未晚于观察点和引文为连续原文；机械有效不代表语义支持。抽查5条不重复的实质结果，少于5条的缺口不得分。输出/显式历史预算超限、引文不连续、状态不符最多部分分；未来/不存在来源、严重协议错误、可回答题空结果上限0，语义由人工进一步判断。

不评分构建/查询耗时；看门狗仅防挂死，可以由面试官调整。构建token及倍率均只报告，不加扣分，不设效率分档或质量准入门槛，不要求特定效率实现。

## 构建 token 计量（参考，不计分）

统计四次正常导入：空存储初始、追加增量、重复初始、重复增量。不要计入开发AI编程工具、查询、评测器、判分工具及故障注入的消耗。

每次ingest按模型汇总一行：

```json
{"complete":true,"models":[{"model":"实际模型标识","kind":"generation","input_tokens":12345,"output_tokens":1234,"cached_input_tokens":0,"measurement":"api_usage"}]}
```

数字只是字段格式示例。`kind` 可为generation、embedding、rerank；`measurement` 为api_usage或tokenizer_estimate。无调用明确返回 `{"complete":true,"models":[]}`。统计不完整或构建未完成用 `complete:false`，保留已知明细；未知不能填0。embedding向量维数、rerank分数不算生成输出，其output_tokens为0。

累计输入I包括提示词、原始对话、旧记忆重读、合并、校验、修复、重试及embedding/rerank输入。缓存是输入子集，不能再次相加。累计生成输出O包括后来丢弃、覆盖、修复的输出；计费推理token遵循服务usage，若已包含在输出总数就不重复计。最终记忆大小不能替代累计生成量。请在说明中写明自报usage的采集方式和是否实际完成服务端独立核对。

面试官按每个模型的实际tokenizer分别编码两份**原始完整JSONL文件**，两者相加得B：包括ID、role、元数据和换行；不含你的提示词；分母只计一次且绑定文件hash。不能使用字符数代替token数。

`R_in = Σ_m(I_m / B_m)`；`R_out = Σ_generation_models(O_m / B_m)`。单生成模型时分别I/B、O/B。多模型先分别归一化后求和，不直接用不同tokenizer的token总数相除。缺usage、构建失败或分母无法确定时相应倍率为null并解释原因；不阻止质量/工程评分。倍率不等于货币成本。

## 两小时结束时一次性交付

- 源码、依赖版本/安装说明、可执行统一入口 `run.sh`。
- 不超过一页的设计与使用说明：运行方式、记忆结构/更新/观察点策略、错误处理、模型配置（如使用）和计量方式。该一页限制针对你的说明，本题面不受此限制。
- 可运行测试及实际测试结果；不要声称未执行的测试已通过。
- 支持面试官从空存储重建和导出构建产物；可附自己构建的产物用于参考，不替代重建验收。
- API Key不写入源码；使用模型时说明环境变量和服务依赖，由面试方准备可用运行环境。可选择完全本地、无模型方案。
